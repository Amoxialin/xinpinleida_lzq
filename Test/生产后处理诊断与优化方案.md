# 生产后处理诊断与优化方案（基于 1049 条真实生产数据实测）

> 版本 v1.0 ｜ 2026-11-18
> 数据源：`new_datasets_仅清洗.xlsx`（训练，140,462 行）× `真实文本数据_1000条.csv`（生产，实测 1,049 行）
> 探测脚本：`_selftest/probe_prod_vs_train.py` / `probe_prod_vs_train2.py` / `probe_prod_vs_train3.py`（输出 txt 同目录）

---

## 0. 三句话结论

1. **当前后处理在生产上有两个硬性天花板**：top15 截断把 micro 召回上限压死在 **85.1%**；汉字<30% 脏过滤在生产 OCR 上误丢 **33.4%** 片段，导致 **25.6% 的帖子**至少一个标签的证据整篇消失。
2. **报告里的模型成绩（micro-F1=0.599 / macro-F1=0.183）没有跑赢一个不用模型的检索基线**——"片段==训练文本→抄标签"实测 micro-F1=0.502 / **macro-F1=0.222**，macro 反超模型 3.9pt。模型目前没学到泛化。
3. **生产数据自带金标签（`标签去重`列，1049 行 100% 非空）**——这是现成的离线评测集，所有阈值/规则都应该拿它校准，而不是继续拍脑袋。

## 1. 两侧数据真实形态（实测）

| 维度 | 训练数据 | 生产数据 |
|---|---|---|
| 粒度 | 片段级证据（一行=样本×片段×标签） | 帖子级（一行=一个视频/图文帖） |
| 规模 | 140,462 行 / 9,436 样本 | **1,049 帖**（不是 1000） |
| 文本长度 | p50=8，mean=10.0，max=192 | 5 路合并后 p50=621，mean=1,048，max=32,915 |
| 标签数 | 475 | 322（**321 个在训练词表内，OOV 仅 1 个：`浮粉`**） |
| 每样本标签 | ≈14.9 个/帖 | mean=10.6，p90=21，**max=49** |
| 文本来源 | 人工标注短证据 | content 97.6% 非空 / OCR 87.4% / title 36.2% / video+asr 各 0.8% |
| 片段数/帖 | — | 切分后 mean=100.8，p50=60，p90=249，max=1,450 |

关键结构事实：
- OCR 列 **95.5% 含真实换行**（不是字面 `\n` 转义），分句正则含 `\n` 时块能正常切开；OCR 单块长度 p50=6、mean=8.2，**与训练片段分布（p50=8）天然对齐**——切分路线本身是对的。
- `content` 有 3 行达到 32,767（Excel 单元格上限），存在源头截断，量小但需向数据方确认。
- 切分后片段 **重复率 57.3%**（70,353 kept → 30,024 唯一），"珀莱雅"一个片段跨帖出现 718 次。
- 过滤后片段 ≤18 字占比 92.2% vs 训练 90.2%——长度分布对齐良好；>32 字需滑窗的仅 1.6%。

**→ 好消息：训练/生产片段分布对齐这件事已经成立。问题全部出在后处理规则和聚合架构上。**

## 2. 问题清单（按严重度排序，全部有实测证据）

### P0-1 ｜ top15 截断把召回天花板压死在 85.1%

- 211 帖（20.1%）金标签 >15 个；最多的一帖有 49 个金标签。
- top15 下 micro 召回天花板 = 9,494/11,155 = **85.1%**；top20→92.3%，top25→96.0%，top30→98.3%。
- 这是与模型无关的硬上限：报告里 R 上不去，先别怪模型。

### P0-2 ｜ 脏过滤（汉字<30%）在生产上误丢 33.4% 片段

- 生产切分出 105,697 个片段，**35,344 个（33.4%）被丢弃**——训练侧同规则误杀率仅 4.42%，生产放大 7.6 倍。原因：OCR 场景天然高比例数字/符号/英文（品牌 logo、规格表、价签、序号）。
- 被丢片段中 **3,456 个精确命中训练文本**（= 有标注金标签的有效证据被直接扔掉），涉及 28 个标签。
- 误杀 TOP：`品牌提及` 2,981 次（PROYA、SOS、①PROYA 等纯英文品牌名汉字占比=0%）、`软广` 247、`B5` 53、`平价/性价比` 52、规格行 `③双抗水160ml+乳120ml`。
- 文档级后果：**269/1,049 帖（25.6%）** 至少一个标签的可检出证据被过滤到整篇消失（品牌提及 128 帖、平价/性价比 45 帖、软广 29 帖、B5 29 帖）。

### P0-3 ｜ 模型 macro-F1（0.183）低于无模型检索基线（0.222）

用"kept 片段 == 训练文本 → 直接抄标签"做纯检索（不用任何模型）：

| 方案 | micro-P | micro-R | micro-F1 | macro-F1 |
|---|---|---|---|---|
| 检索基线（含脏过滤） | 0.440 | 0.583 | 0.502 | **0.222** |
| 检索基线（不做脏过滤） | 0.443 | 0.599 | 0.510 | — |
| 报告模型成绩 | — | — | 0.599 | 0.183 |

- micro 上模型只比"背训练集"高 +0.097；**macro 上模型反而低 0.039**。
- 说明当前模型对长尾标签的输出质量还不如精确查表。在模型真正学好之前，检索兜底是免费的下界保证。

### P1-4 ｜ 94 个"文档级标签"（占金标签量 5.9%）片段分类天然检不出

对 322 个生产标签按"金标签词在整帖字面出现率 / 检索支持率"分层：

- **片段级 185 个**：证据存在于单一片段（双抗精华、麦角硫因、虾青素、视黄醇A醇……），片段分类架构适用；
- **半可检 43 个**：补水保湿、种草、平价/性价比、发黄——部分帖有片段证据，部分没有；
- **文档级 94 个**：舒缓镇定(60帖)、日常分享(57)、一瓶多效(48)、明星同款(36)、主播推荐(33)、游戏联名(32)、网红爆款(24)、自用好物分享(23)……**证据是整帖语义/上下文判断，不落在任何片段上**。
- 文档级标签占金标签总出现量 655/11,155 = **5.9%**——这部分是现架构下不可消除的结构性 FN。注意 `品牌提及` 字面率 0% 但检索支持率 67%（靠品牌词片段检出），属于"靠词典能救"的伪文档级标签。

### P1-5 ｜ 长帖下 max 聚合 + 全局阈值 0.5 → precision 崩

- 每帖平均 100.8 个片段，max 聚合意味着**任意一个片段误报，整帖就挂上该标签**。片段数越多，"至少一个噪声片段越过 0.5"的概率越高——长帖和短帖用同一阈值完全不合理。
- 检索基线 P=0.440（FP 8,284 > TP 6,507）已经侧面印证这个聚合方式的 precision 压力。

### P1-6 ｜ 支持率≥2% 规则在 57.3% 重复率下失真

- 支持率按未去重片段计数：同一段 OCR 品牌词重复几十次会推高品牌类标签支持率；而长尾标签真实证据只有 1~2 票，在长帖（250 片段 → 2%=5 票门槛）下被直接压死，在短帖（5 片段 → 2%=0.1 票）下又形同虚设。
- 同一条规则在两端都不工作。

### P2 级问题（已知/影响小）

- **P2-7** 分句半角 `.` 小数点 bug：训练 5.70% 文本含"数字.数字"（7.5ml、68.5/支），生产价签同样会被切碎。
- **P2-8** 训练 475 标签中 **154 个（32.4%）在 1,049 帖生产数据中从未出现**——这些标签对生产只贡献 FP 概率质量，不贡献召回。
- **P2-9** 3 行 content 达 Excel 32,767 上限（源头截断），影响极小但需向数据方确认导出链路。

## 3. 优化方案（与问题一一对应，可直接落地）

### Opt-1 白名单式脏过滤（替换 30% 汉字一刀切）→ 治 P0-2

```python
CJK   = re.compile(r"[\u4e00-\u9fff\u3400-\u4dbf]")
PRICE = re.compile(r"[¥￥$]\s*\d|券后|\d+(?:\.\d+)?\s*(?:元|块|折|/支|/瓶|/盒)")
SPEC  = re.compile(r"\d+(?:\.\d+)?\s*(?:ml|g|片|支|瓶|盒|袋|装)", re.I)
SEQ   = re.compile(r"[①②③④⑤⑥⑦⑧⑨⑩]")
# 品牌词典：直接从训练集"品牌提及"标签的全部证据文本自动构建 + 人工补充
BRAND = {"proya", "sos", "cpb", "sk2", "skii", "..."}

def keep_fragment(frag):
    f = frag.strip()
    if len(f) < 2:
        return False
    if len(CJK.findall(f)) / len(f) >= 0.30:
        return True
    low = f.lower()
    if any(b in low for b in BRAND):          # 纯英文/混合品牌名
        return True
    if PRICE.search(f) or SPEC.search(f):     # 价格、规格行
        return True
    if SEQ.search(f) and len(f) >= 4:         # 带圈序号的清单行
        return True
    return False
```

预期：找回 269 帖被整篇误杀的证据；检索口径 R 0.583→0.599 是无过滤下界，白名单会更高（部分被丢片段含未过滤口径没算到的证据）。

### Opt-2 取消 top15，改"逐标签阈值 + top30 兜底" → 治 P0-1

召回天花板 85.1%→98.3%。precision 不靠数量截断控制，靠 Opt-4 的阈值控制。

### Opt-3 检索兜底 + 模型增量的混合推理 → 治 P0-3

```
if 片段 in 训练文本→标签映射:  直接输出映射标签（地板 F1=0.502/0.222）
else:                          模型预测，过阈值才输出
最终标签 = 两路并集（可按概率重排）
```

macro-F1 从此有 ≥0.222 的保底，模型只负责在未见过的表达上做增量。零训练成本，一天可上线。

### Opt-4 聚合改 noisy-OR + 逐标签阈值 → 治 P1-5

```
doc_score(l) = 1 - Π_i (1 - p_i(l))     # 或 top3-mean，替代 max
```

- 用 1,049 帖金标签拆 dev 集逐标签校准阈值（高频标签阈值高、长尾标签阈值低），替代全局 0.5；
- 长帖按片段数做归一化（如 score / log(1+n_frags)），避免长帖天然更容易误报。

### Opt-5 支持率先去重、改绝对票数 → 治 P1-6

片段按文本 hash 去重后再计票；规则改为 `票数 ≥ k_l`（k 按标签频率分档：高频 3 票、长尾 1 票），弃用百分比。附带收益：推理时对 30,024 个唯一片段打分即可，**省 57% 计算量**。

### Opt-6 两阶段架构：片段分类器 + 文档分类器 → 治 P1-4

- 第一阶段（现有模型）：负责 185 个片段级标签；
- 第二阶段（新增轻量模型）：输入 = title + content 前 512 字 + **第一阶段输出的片段标签概率聚合向量**（不用重新编码长文），负责 94 个文档级 + 43 个半可检标签；
- 消除 5.9% 的结构性 FN，文档级标签（舒缓镇定/日常分享/明星同款/主播推荐等）只有这一条路能检出。

### Opt-7 输出标签白名单 → 治 P2-8

推理输出只保留生产活跃标签集（当前 322 个），154 个生产中从未出现的训练标签直接屏蔽。纯 precision 提升、零风险（前提：与业务确认生产标签体系不启用这些标签）。

### Opt-8 分句保护小数点 → 治 P2-7

```python
PROTECT = re.compile(r"(?<=\d)\.(?=\d)")
text = PROTECT.sub("<DOT>", text)
parts = [p.replace("<DOT>", ".") for p in SPLIT.split(text)]
```

### Opt-9 把 1,049 帖金标签用成正规评测集（贯穿所有优化）

- 拆 ~200 帖做 **dev 集**：调阈值、调 k 票、调白名单；
- 其余 ~849 帖做 **test 集**：只在最终报分时用一次；
- **禁止**在同一批数据上反复调参又报分（当前报告的评测就有此嫌疑）；
- 后续每期生产数据都保留金标签列，形成滚动评测集。

## 4. 落地优先级与预期收益

| 优先级 | 改动 | 治什么 | 成本 | 预期收益（实测支撑） |
|---|---|---|---|---|
| **1** | Opt-1 白名单脏过滤 | P0-2 | 低（1天） | 269 帖（25.6%）证据找回；品牌提及/软广/平价召回显著回升 |
| **2** | Opt-2 取消 top15→top30 | P0-1 | 极低（改配置） | 召回天花板 85.1%→98.3% |
| **3** | Opt-7 输出标签白名单 | P2-8 | 极低 | 屏蔽 154 个僵尸标签，纯 precision 提升 |
| **4** | Opt-3 检索兜底混合推理 | P0-3 | 低（1天） | macro-F1 保底 ≥0.222（超过当前模型） |
| **5** | Opt-5 支持率去重+绝对票数 | P1-6 | 低 | 长尾召回 + 推理省 57% 算力 |
| **6** | Opt-4 noisy-OR + 逐标签阈值 | P1-5 | 中（需 dev 集调参） | precision 系统性提升，长短帖分别校准 |
| **7** | Opt-6 文档级第二阶段 | P1-4 | 高（再训一个模型） | 消除 5.9% 结构性 FN |
| 8 | Opt-8 小数点保护 | P2-7 | 极低 | 价签/规格证据完整性 |

前 4 项全是低成本工程改动，不动模型、不重训，按检索基线口径估算 micro-F1 可从 0.502 → 0.55+（模型混合后更高）；**当前报告 micro-F1=0.599 里被 top15 和脏过滤吃掉的部分，理论上可收回 5~10pt**。
