## 二、实验设置

### 2.1 数据

| 项目 | 值 |
|---|---|
| 评测集 | `data/real_1000.csv`，**1049 帖** |
| 文本列 | `video_highlight_content` / `audio_asr_content` / `content` / `cover_ocr_content` / `title`（5 路合并） |
| 标签体系 | **475 类**，多标签不互斥 |
| 金标签总数 | 11154，**平均每帖 10.63 个**（中位 8，p90=21，max=49） |
| 词表外金标签 | 仅 **1 种 / 1 次**（标签体系覆盖度良好） |
| 训练集 | `data/yft_train.json` 24851 条 / 475 标签 / 40 epoch |

### 2.2 训练协议（保证公平对比）

- 11 个模型统一超参：`embedding=128`、`batch=128`、`Adam lr=0.002`、`dropout=0.3`、`BCEWithLogitsLoss`
- 每个模型独立 `checkpoint_dir` 与 `dict_dir`，支持并发训练互不干扰
- **11 份字典 md5 完全相同**，且与线上 `dict_yft` 一致 → 标签空间无偏差
- 批1 六并发 + 批2 五并发，总训练耗时 28 分钟

### 2.3 方法学自证（关键）

重训的 `TextRNN`（40 epoch / 独立字典）与**线上 `TextRNN_best`**（50 epoch）在 real_1000.csv 上指标**逐位相同**：

```
F1=0.5664   P=0.5759   R=0.5572   （两者完全一致）
```

这证明字典、数据划分、后处理链路与线上完全对齐，**下文所有对比都是模型/后处理本身的差异，不是配置差异造成的假象**。

### 2.4 统一后处理基线（"旧脚本"配置）

```
滑窗 chunk=32（步长自动 = chunk/2 = 16）
min_chunk=2      丢弃短于 2 字的碎片
min_cn_ratio=0.3 汉字占比 <30% 的片段丢弃（过滤 OCR 价格/时间戳）
聚合 agg = 各片段概率的 max
min_support=-0.02 支持率 ≥2% 片段
max_labels=15    每帖按概率取前 15
```

片段规模：总片段 **90905**，全局去重后推理 **35616**（去重节省 **60.8%**），单次评测 18.4s。

## 四、分布偏移诊断（本次最重要的发现）

### 4.1 长度分布相差 58.7 倍

| 数据集 | 中位长度 | p90 | max |
|---|---|---|---|
| `yft_test`（训练同源） | **9 token** | 17 token | 103 token |
| `real_1000.csv`（评测） | **528 字符** | 2224 字符 | 32807 字符 |

滑窗切分后每帖片段数：**中位 50，均值 86.7，p90=206，p95=260，max=1965**（1 帖无有效文本）。

## 五、后处理消融与新旧脚本对比

共 **114 组**后处理实验（TextRCNN 79 组 + 线上基线 35 组），全部在 real_1000.csv 实跑。

### 5.1 一个被忽视的事实：支持率规则有一半时间是空转的

```python
need = min_support if min_support >= 1 else max(1, ceil(-min_support * n_chunks))
ok   = (agg > threshold) & (support >= need)
```

默认 `min_support=-0.02` → `need = ceil(0.02 × 片段数)`。而 `agg` 是各片段概率的 **max**，`agg > threshold` 天然蕴含"至少 1 个片段过阈值"，即 `support ≥ 1`。因此：

| 片段数 | need | 该过滤是否生效 | 帖子占比 |
|---|---|---|---|
| ≤ 50 | 1 | **恒成立，完全空转** | **50.8%** (533/1049) |
| > 50 | ≥2 | 生效 | 49.2% (516/1049) |

消融印证：`min_support=0`（显式关闭）与 `min_support=1` 结果**完全相同**（F1=0.6207），而默认 `-0.02` 为 0.6195，差异仅 0.0012。

> **两个模型的最优后处理收敛到同一套参数**，只有阈值不同（基线 0.45 / TextRCNN 0.35）——说明这套参数反映的是**数据本身的长度特性**，而非某个模型的偏好，可迁移性强。

### 5.4 关键诊断：长帖召回崩塌（比调参重要得多）

按每帖片段数分组统计（TextRCNN @thr0.3，默认后处理）：

| 片段数区间 | 帖数 | 均片段 | 均预测 | 均金标 | microP | microR | microF1 |
|---|---|---|---|---|---|---|---|
| 0-25 | 373 | 11 | 8.5 | 7.1 | 0.6680 | **0.8004** | **0.7282** |
| 25-50 | 160 | 40 | 14.0 | 12.9 | 0.6382 | 0.6900 | 0.6631 |
| 50-100 | 214 | 73 | 11.0 | 11.8 | 0.6096 | 0.5730 | 0.5907 |
| 100-200 | 189 | 142 | 9.1 | 12.2 | 0.6601 | 0.4933 | 0.5646 |
| 200-400 | 100 | 253 | 7.9 | 14.5 | 0.6413 | 0.3497 | 0.4526 |
| 400+ | 13 | 970 | 4.8 | 12.8 | 0.4286 | **0.1627** | **0.2358** |

**召回随帖长单调崩塌（0.80 → 0.16），而精度几乎不变（0.67 → 0.43）、FP 率仅从 0.331 升到 0.357。**

这排除了"max 聚合对长帖抽样上偏导致误报"的假设——问题不在误报，而在**漏报**。根因正是 5.1 那条支持率规则：

- 片段数 253 的帖 → `need = ceil(0.02×253) = 6`，一个标签必须在 ≥6 个片段上过阈值才算命中
- 但长帖里一个话题往往只出现在少数几个片段中（例如 253 个片段里的 3 个）→ 被系统性压掉
- 短帖 `need=1` 完全不过滤 → 召回 0.80

**预测/金标签比值同样暴露问题**：短帖 1.20（过度预测），长帖 0.38（严重欠预测）。

> 这条规则当前 CLI **无法表达正确形态**：`--min-support 2` 会把 need 对**所有**帖子统一设为 2，短帖也被收紧，实测 −0.0777。正确形态是"按比例算、但对长帖封顶"，必须改代码。

### 5.5 新脚本 `test_val_yft_v2.py`

以 `test_val_yft.py` 为基础复制改造，**运行方式完全不变**（同样的 CLI、同样的 `--run-dir`、同样的 `run.log` / `run_meta.json` / `test-val_predicted.csv` / `test_val_per_label.csv` 产物）。新增 4 个参数：

| 参数 | 作用 |
|---|---|
| `--support-cap N` | **核心修复**：比例式 need 的封顶，`need = min(ceil(0.02n), N)`。短帖不受影响，长帖恢复召回。0=不封顶（旧行为） |
| `--agg max\|mean\|topk` | 片段概率聚合方式，默认 `max`（旧行为） |
| `--agg-topk K` | `topk` 时取概率最高的 K 个片段求均值 |
| `--save-chunk-probs` | 落盘**片段级**概率矩阵，之后调后处理规则可离线复算、无需重跑推理 |

**等价性验证（改造正确性的硬门槛）**：默认参数下 v2 与 v1 在 11 项指标上**逐位一致**：

另一处自证：`--agg topk --agg-topk 1` 的结果与 `--agg max` **完全相同**（F1=0.6397），符合数学预期（top-1 均值即最大值）。

### 6.3 失败归因（不止报数字）

- **Opt-1 为何失败**：白名单过滤把丢弃率从 30.4% 降到 20.0%（保留片段 90905→104528，+15%），但 test 上 **ΔTP=−273**——多保留的片段绝大多数是 OCR 噪声，不但没捞回金标签，还在 max 聚合下稀释/顶掉了真信号。文档假设"cn-ratio 一刀切误伤含数字的正常讨论"，实测被误伤部分的金标签密度极低。
- **Opt-7 为何空转**：475 个标签中 156 个是僵尸标签（训练频次极低），但**模型本来就几乎不预测它们**（加白名单后 ΔFP 仅 −10）。dev 源白名单的 +0.0035 来自砍掉少量 FP，代价是误杀真长尾（macro −0.0197）。
- **Opt-5 绝对票数为崩**：绝对票数对长帖（数百片段）过松、对短帖过紧，等于把 support_cap 刚修好的长度偏差又加了回去且更猛。文档 Opt-5 中"**去重计票**"与"**绝对票数**"必须拆开看：前者 +0.0048 有效，后者 −0.1076/−0.1864 有害。
- **Opt-4 两个成分都负面**：noisy-OR+逐标签阈值在 200 帖 dev 上校准，dev +0.0055 / test −0.0063，是典型的小样本校准过拟合；长帖归一化直接 −0.4545，因为它把几百个片段的低置信分数系统性抬过阈值。
- **Opt-3 是业务权衡而非技术问题**：检索兜底 +2046 TP 的代价是 +6342 FP（micro −0.0430），但召回从 0.5993 拉到 **0.8260**、macro +0.0843——它确实覆盖了大量模型够不着的长尾标签。**若目标是 microF1 应放弃；若目标是"尽量打标、可容忍误报"或长尾覆盖，可单独灰度。**
