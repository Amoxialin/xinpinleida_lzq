# 美妆社区帖子多标签打标方案汇报

> 任务：对美妆社区帖子（含正文、标题、视频高光、语音 ASR、封面 OCR 共 5 路文本）自动打标，标签体系共 **478 类**（软广、品牌提及、平价、变白、防晒防护等），一个帖子可同时命中多个标签。

---

## 一、整体方案架构

```
┌─────────── 训练侧 ───────────┐   ┌──────────────── 推理侧 ────────────────┐
│ 已标注短文本 34493 条          │   │ 帖子5列文本合并                          │
│   ↓ 8:1:1 划分               │   │   ↓                                     │
│ train 27584/dev 3456/test 3453│  │ 标点分句 + 滑动窗口切片(32字/步长16)       │
│   ↓                          │   │   ↓                                     │
│ TextRNN(BiGRU+Attention)     │   │ 脏片段过滤(汉字占比<30%丢弃)              │
│ 多标签分类模型                │   │   ↓                                     │
│   ↓                          │   │ GPU批量推理(batch 512, 片段全局去重)      │
│ checkpoint: TextRNN_best     │──→│   ↓                                     │
│ (最优 epoch 11)              │   │ 聚合判定: max概率 + 阈值0.5               │
└──────────────────────────────┘   │           + 支持率≥2% + 每帖top15        │
                                   │   ↓                                     │
                                   │ 帖子级标签 + 指标/明细CSV                 │
                                   └─────────────────────────────────────────┘
```

核心设计思想：**训练用干净的短文本学"什么文字对应什么标签"，推理用滑动窗口把长帖子拆成同分布的短片段逐个判定，再按规则合并回帖子级标签**——用工程手段弥合"训练短文本 vs 推理长帖子"的分布差异，不需要昂贵的整帖重新标注。

## 二、训练方案

### 2.1 数据

| 项目 | 内容 |
|---|---|
| 数据来源 | 人工标注的短文本-标签对（yft.jsonl），共 34493 条 |
| 划分 | train 27584 / dev 3456 / test 3453（8:1:1，随机） |
| 文本形态 | 短文本，中位长度 9~10 字 |
| 标签 | 478 类，多标签（一条文本可多个标签），标签间不互斥 |

### 2.2 模型与超参

| 项目 | 配置 | 说明 |
|---|---|---|
| 框架 | NeuralNLP-NeuralClassifier（腾讯开源） | 多标签分类成熟框架 |
| 模型 | TextRNN：**双向 GRU**（hidden 64，1 层）+ **Attention 文档嵌入**（dim 16） | 经模型选型对比后确定（见 2.3） |
| 词嵌入 | 随机初始化，128 维，词表上限 20000 | 语料为中文短文本，随机嵌入即可收敛 |
| 输入长度 | max_token_len = 64 | 覆盖训练文本长度分布 |
| 损失 | BCEWithLogitsLoss（逐标签二分类） | 多标签标准做法 |
| 优化器 | Adam，lr=0.002，batch=128，dropout=0.3 | 训练 50 epoch，取验证集最优 checkpoint（epoch 31） |

### 2.3 模型选型与训练结果（框架内部 test 集，短文本同分布评测）

训练过程中对比了三种配置：

| 模型配置 | micro F1 | macro F1 | 说明 |
|---|---|---|---|
| TextCNN | 0.656 | 0.319 | 卷积捕捉局部 n-gram 特征 |
| TextRNN：BiGRU + **AVG** 池化 | 0.618 | 0.211 | 第一版，平均池化淹没关键信息 |
| TextRNN：BiGRU + **Attention**（最终采用） | 0.634 | 0.283 | 池化改为 Attention 后 F1 +1.6pt、macro +7.2pt |

**最终模型（BiGRU+Attention）成绩**：

| 指标 | 值 |
|---|---|
| 验证集 micro F1 | 0.651（P=0.612, R=0.697，epoch 31） |
| 测试集 micro P / R / F1 | 0.597 / 0.676 / **0.634** |
| 测试集 macro F1 | 0.283 |

> macro 明显低于 micro：478 类中大量长尾标签（78 个标签训练样本 < 10 条），头部标签表现良好。这是后续数据治理的重点（见第六节）。

## 三、推理与后处理方案（滑动窗口 + 聚合规则）

### 3.1 为什么需要滑动窗口

真实帖子是长文本：5 列合并后中位 278 字、均值 740 字、最长上万字；而模型训练时只见过中位 9~10 字的短文本，且输入上限 64 token。**直接把整帖截断喂给模型会丢失 90% 以上信息**，因此采用滑动窗口把长帖拆成模型"认识"的短片段。

### 3.2 推理流水线（test_val_yft.py，共 5 步）

**① 文本合并**：5 列（video_highlight / audio_asr / content / cover_ocr / title）按换行拼接为整帖文本。

**② 分句 + 滑动窗口切分**：
- 先按标点和换行分句（保证片段语义边界自然）；
- 超过 32 字的句子以 **窗口 32 字、步长 16 字** 滑动切片（相邻片段重叠 50%，避免标签证据被窗口边界切断）；
- 片段全局去重：137696 个片段去重后仅 43488 个，**推理量节省 68%**（重复的模板话术只算一次）。

**③ 脏片段过滤（关键步骤）**：
- 分析发现 **30.2% 的片段是 OCR/ASR 噪声碎片**：出现频次最高的片段是"00"（2047 次，OCR 时间戳/价格碎片），其余如"http""cn""5ml""+22""￥1"、纯数字等；
- 这类碎片在训练数据中从未出现，模型对其输出接近随机，是误报的最大来源；
- 规则：**汉字占比 < 30% 的片段直接丢弃、不进模型**（过滤后片段 137696 → 96101）。

**④ GPU 批量推理**：batch 512，每片段输出 478 维 sigmoid 概率，全量 1419 帖推理约 5 秒。

**⑤ 帖子级聚合判定**（每个标签独立判定）：

| 规则 | 参数 | 作用 |
|---|---|---|
| max 聚合 | 标签概率 = 所有片段中的最大值 | 标签证据只要出现在任一干净片段即可检出 |
| 阈值 | 0.5 | 低于 0.3 时误报失控（见第四节实验） |
| **支持率过滤** | 标签须在 **≥2% 的片段**上超过阈值 | 压制"单个噪声片段偶发点亮"型误报 |
| 每帖标签上限 | top 15（按概率取前 N） | 金标签中位数仅 6 个/帖，限制过度输出 |

### 3.3 聚合规则的设计依据："抽奖效应"

初版方案（任一片段过 0.3 即命中）精确率仅 0.048——平均每帖误报 151 个标签。根因是**误报机会随片段数线性累积**：

| 帖子长度（片段数） | 行数 | 平均误报/帖 | 行级精确率 |
|---|---|---|---|
| <5（短帖） | 370 | 0.0 | **0.898** |
| 5-15 | 189 | 1.6 | 0.636 |
| 16-40 | 174 | 5.2 | 0.551 |
| 41-100 | 259 | 17.9 | 0.339 |
| >100（长帖） | 427 | **36.9** | **0.199** |

即使每个脏片段只有 2% 概率随机点亮某标签，100 个片段下该标签至少误报一次的概率就是 1-0.98¹⁰⁰ ≈ **87%**。因此单纯调阈值治标不治本，必须"过滤脏片段（减少抽奖次数）+ 支持率过滤（要求多次中奖才算）"双管齐下。短帖 0.898 的精确率证明：**只要片段质量接近训练分布，模型本身是可靠的。**

## 四、参数调优实验记录

评测集：`test-val.csv`，**1419 条真实帖子**（整帖 5 列文本 + 人工金标签），金标签共 11079 个，中位 6 个/帖、最多 43 个。所有实验统一在此集上进行。

| # | 配置 | micro P | micro R | micro F1 | 结论 |
|---|---|---|---|---|---|
| 1 | 阈值0.3，无任何限制（初版） | 0.048 | 0.937 | 0.092 | 误报失控，平均每帖报151个标签 |
| 2 | 阈值0.5 + top15 | 0.500 | 0.621 | 0.554 | 阈值/top_k 扫描出的最优点 |
| 3 | 实验2 + 支持率≥2%片段 | 0.611 | 0.523 | 0.563 | 支持率过滤有效压制偶发误报 |
| 4 | 实验2 + 支持率≥5% | 0.729 | 0.302 | 0.427 | 过严，召回崩塌 |
| 5 | 实验2 + 支持率≥10% | 0.848 | 0.169 | 0.282 | 精确率导向的极限操作点 |
| 6 | 只用 content 列（不合并5列） | 0.596 | 0.443 | 0.509 | 证明金标签覆盖全帖信息，不能只用正文 |
| 7 | **实验3 + 脏片段过滤(汉字占比≥30%)** | **0.644** | **0.560** | **0.599** | **最终方案：P、R 同时提升** |
| 8 | 实验7 但汉字占比阈值 0.5 | 0.639 | 0.560 | 0.597 | 与 0.3 基本持平，取 0.3 保留更多品牌英文名片段 |

关键结论：
1. **实验 7 是少数"P 和 R 同时上升"的改动**——因为脏片段过滤移除的是纯噪声（只会产生误报、几乎不承载真实标签证据），同时片段总数减少 30% 使支持率分母更纯净；
2. 支持率是 P/R 跷跷板：2%→5%→10% 对应 P 0.64→0.73→0.85、R 0.56→0.30→0.17，**业务可按场景选择操作点**（默认取 F1 最优的 2%）；
3. 全部调优均为推理侧规则，**不需要重新训练模型**。

| Hamming 准确率 | 0.988 | 标签位级判对比例 |
| TP / FP / FN | 6209 / 3436 / 4870 | — |

相比初版方案：**精确率 0.048 → 0.644（13 倍），F1 0.092 → 0.599（6.5 倍）**；相比仅调阈值的版本：F1 0.554 → 0.599。

### 阈值敏感性扫描（真实数据 1419 帖，完整流水线实测）

固定其他最优配置（脏片段过滤 0.3 + 支持率≥2% + 每帖 top15），仅改变判定阈值，0.3~0.9 全量实测：

| 阈值 | micro P | micro R | micro F1 | sample级 F1 | macro F1 | exact match | TP / FP / FN | 预测标签总数 |
|---|---|---|---|---|---|---|---|---|
| 0.3 | 0.578 | **0.625** | **0.601** | 0.599 | 0.186 | 0.226 | 6922 / 5046 / 4157 | 11968 |
| 0.4 | 0.610 | 0.591 | 0.600 | 0.597 | 0.183 | 0.229 | 6543 / 4180 / 4536 | 10723 |
| **0.5（默认）** | **0.644** | 0.560 | 0.599 | 0.593 | **0.183** | **0.230** | 6209 / 3436 / 4870 | 9645 |
| 0.6 | 0.679 | 0.512 | 0.584 | 0.574 | 0.169 | 0.233 | 5672 / 2678 / 5407 | 8350 |
| 0.7 | 0.705 | 0.453 | 0.551 | 0.538 | 0.149 | 0.229 | 5015 / 2104 / 6064 | 7119 |
| 0.8 | 0.744 | 0.384 | 0.507 | 0.496 | 0.127 | 0.228 | 4258 / 1465 / 6821 | 5723 |
| 0.9 | 0.786 | 0.270 | 0.402 | 0.385 | 0.091 | 0.226 | 2991 / 813 / 8088 | 3804 |

解读：

1. **F1 在 0.3~0.5 区间是平台期**（0.599~0.601，差异 <0.2 个点），0.5 以上开始单调下降；
2. 默认取 0.5 而非 F1 略高的 0.3：两者 F1 几乎打平，但 0.5 的精确率高 6.6 个点（0.644 vs 0.578）、误报少 1600 个——**人工复核成本更低**，且 exact match 也是全表最高；
3. 阈值是一条清晰的 **P/R 跷跷板**：每 +0.1，P 约 +3~4 个点、R 约 -6~9 个点，业务可按场景切换操作点：
   - 重召回（如舆情监测、标签召回候选池）→ 阈值 0.3~0.4（R≈0.60~0.63）；
   - 重精确（如标签直接对外展示、免人工）→ 阈值 0.7~0.8（P≈0.70~0.74）。
4. 切换阈值只需一条命令：`python test_val_yft.py --threshold 0.7`。

## 六、剩余误差的根因分析

当前 F1≈0.60 的瓶颈已不在推理侧，主要来自**数据与标签体系**：

1. **近义标签未合并，互相制造 FP 和 FN**：如 `平价`↔`平价/性价比`、`补水保湿`↔`保湿补水`，模型报 A 金标签写 B，两边都算错；
2. **标注矛盾**：训练集中发现 692 组"文本相同、标签不同"的矛盾样本，直接压低模型上限，也让 exact match 难以提升；
3. **长尾标签**：78 个标签训练样本 <10 条（31 个 <5 条），这些标签学不会、还贡献随机误报，是 macro-F1 仅 0.18 的直接原因；
4. **标注口径不一致**：部分标签（如 `防晒防护` 金标签仅 13 次，但模型在 170 帖检出且多数合理）疑似金标签只按正文标注，而帖子视频/OCR 中确实存在相关内容——这部分"FP"需要业务侧确认口径后重估。

## 七、下一步优化计划（按性价比排序）

| 优先级 | 措施 | 成本 | 预期收益 |
|---|---|---|---|
| P0 | **逐标签阈值**（tune_threshold_yft.py 已具备）：误报大户单独提阈值（如 0.9），高准标签放宽（如 0.4） | 无需新数据，1 天内可完成 | F1 +2~4 个点 |
| P0 | **标签体系清洗**：合并近义标签、下线训练样本 <5 条的 31 个长尾标签 | 纯规则，零训练成本 | 直接消减一批"冤案 FP"，macro 指标显著改善 |
| P1 | **标注口径对齐**：与标注团队确认金标签是否覆盖视频/OCR 内容，重估真实精确率 | 沟通成本 | 指标可信度 |
| P1 | **困难负样本增强**：把 OCR 脏碎片（价格、时间戳、模板话术）作为负样本加入训练集——**仍保持短文本训练范式**，让模型自己学会对噪声"闭嘴" | 需重训一轮（数小时） | 进一步降低长帖误报 |
| P2 | 清洗 692 组矛盾标注后重训 | 需重训 | 提升模型上限 |

## 附：关键名词速查（汇报答疑用）

- **micro**：把所有帖子的标签判定汇总成一个池子算 P/R/F1，每个标签判定权重相同，是业界默认主指标；
- **sample级**：每帖单独算 P/R/F1 再平均，反映"平均一个帖子的打标体验"；
- **macro**：每个标签单独算再平均，反映长尾标签的学习情况；
- **exact match**：整帖标签集合与金标签完全一致（不多不少）的比例，对应"可完全免人工"的帖子占比；
- **支持率过滤**：要求一个标签在帖子的多个片段（≥2%）上都被检出才算命中，防止单个噪声片段"一次抽奖中奖"就误报。
